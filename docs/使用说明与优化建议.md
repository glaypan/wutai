# 舞台流程表 v6.0.8 使用说明与优化建议

## 版本定位

| 版本 | 适用场景 | 差异 |
| --- | --- | --- |
| 正式版 | 正式演出、稳定值守 | 紧凑界面，减少视觉干扰 |
| beta-design | 排练、移动端和交互验证 | 更明显的视觉与移动反馈 |

两个版本的服务端协议、角色权限、认证、断线恢复、Tally 和审批行为一致。请在不同端口或不同设备上分别启动，避免端口冲突。

## 首次部署

1. 安装 Node.js 18.17 或更高版本。
2. 进入需要运行的版本目录下的 `stage-manager`。
3. 执行 `Copy-Item config.example.json config.json` 和 `Copy-Item show.example.json show.json`。
4. 执行 `npm install`，然后执行 `npm start`。
5. 浏览器打开启动日志中的入口页地址，例如 `http://localhost:3000/`。

部署前执行：

```powershell
npm test
node --check server-standalone.js
```

## 登录与角色管理

入口页会引导到对应端口的角色登录页。密码只通过 POST 请求体发送，登录成功后服务端设置 12 小时会话 Cookie。密码和 Token 不会出现在地址栏、复制链接或二维码中。

控制端在“系统设置/角色权限”中配置导演、助理、后台和控台角色密码与权限。密码保存后即可使用对应角色入口登录，不需要先让控制端在线，也不需要重启服务器。

权限保存后服务端立即广播新版本；已经连接的角色界面会重绘权限，后到达的旧权限消息不会覆盖新状态。只有修改监听端口、字幕端口开关等监听配置时，才需要重启服务使端口变化生效。

提示屏和字幕屏首次访问会显示仅包含提示屏角色的登录页；未设置提示屏密码时可一键进入，设置密码后必须输入密码。提示屏会话与控制端、客户端 Cookie 隔离。

## 日常运行

1. 控制端在入口页登录，确认节目单、通道、时间轴和 OSC/MIDI 配置。
2. 用入口页为导演、助理、后台、控台复制角色入口或显示二维码；接收方自行输入密码。
3. 打开提示屏端口，将页面置于全屏并检查音视频 Cue 的媒体路径。
4. 演出前确认连接状态为已连接；断线后客户端按 1、2、4、8 秒退避重连，并尝试恢复遗漏事件。
5. 用 Tally 向目标角色发送提示；对需要控制端确认的模式切换请求在 60 秒内审批或拒绝。

## 安全与备份

- 不要分享 `config.json`、`show.json`、浏览器 Cookie 或录入密码的截图。
- 通过入口页与角色链接分发入口，不通过 URL 传播密码或 Token。
- 每次演出前复制 `show.json` 到带日期的离线备份目录，并在另一台设备验证可导入。
- 局域网演出使用可信 Wi-Fi 或有线网络；公共网络场景应部署 HTTPS 和反向代理。
- 服务进程重启后内存会话失效，角色需要重新登录，这是预期安全行为。

## 已完成的开发改进

- H1：事件序号、有限缓存、动作幂等和断线恢复。
- H2：Tally 状态机、确认/忽略/超时、历史记录与在线分发。
- H3：模式切换审批、超时、拒绝原因、备注和审计记录。
- H4：移动端 Pointer Events、左右滑动、顶部下拉刷新、长按识别、安全区域和触控目标。
- 认证：POST 密码登录、HttpOnly 会话 Cookie、同源 WebSocket Cookie 鉴权和 Origin 校验。
- 权限：版本化广播与客户端防回退，权限调整不依赖服务重启。

## 后续优化建议

| 优先级 | 建议 | 收益 |
| --- | --- | --- |
| P0 | 现场演出前增加一键健康检查 | 检查端口、WebSocket、媒体文件、OSC/MIDI 设备和磁盘空间，减少开演前人工遗漏。 |
| P0 | 为提示屏增加设备白名单 | 在不可信局域网中进一步缩小提示屏访问面。 |
| P1 | 增加加密备份与版本化节目单恢复 | 支持按时间点回滚节目单、权限和媒体引用。 |
| P1 | 建立端到端浏览器测试 | 覆盖角色登录、重连、权限即时收敛、Tally、审批和移动端手势。 |
| P1 | 增加操作审计导出 | 以 CSV/JSON 导出关键操作、审批和异常，便于复盘。 |
| P2 | 接入 HTTPS 与局域网证书部署脚本 | 降低跨设备部署和 Cookie 传输风险。 |
| P2 | 支持多演出项目切换 | 在同一服务器内隔离节目单、媒体、权限和审计数据。 |
| P2 | 建立发布流水线 | 自动执行测试、生成压缩包、附加校验和并发布 GitHub Release。 |

## 持续开发约定

- 新功能先在两版共享协议和 `stage-core.js` 中定义契约，再分别实现界面差异。
- 修改认证、权限或实时协议必须同时补充两版测试并执行 `npm test`。
- 真实配置、节目数据、运行日志、媒体文件不提交到 Git。
- 每个演出版本在现场使用前单独做桌面与移动端回归；不要用 beta-design 替代未验证的正式版。
